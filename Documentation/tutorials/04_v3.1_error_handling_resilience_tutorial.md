# Corvus v3.1 Tutorial: Enterprise Error Resilience & Diagnostics

**Version 3.1** introduced an **Enterprise Error Handling & Resilience Engine** designed to eliminate cryptic segmentation faults and unhandled syntax crashes across the interpreter and compiled binaries.

---

## 1. Visual Call-Stack Tracebacks & Caret Pointers

When syntax or runtime errors occur, `CorvusDiagnosticEngine` formats a precise developer traceback:

```text
======================================================
[Corvus NameError]
--> Location: File 'app.crv', Line 14, Column 5:
    14 |     set score = score + undefined_variable
       |                         ^^^^^^^^^^^^^^^^^^

Details: Undefined variable 'undefined_variable'.
Fix Hint: Verify that 'undefined_variable' is declared in this scope.
======================================================
```

---

## 2. Panic-Mode Parser Recovery (`synchronize()`)

Instead of stopping on the first syntax error, the parser calls `synchronize()` to skip to the next statement boundary (`[`, `]`, `;`, `var`, `func`, `if`), reporting all syntax errors in a source file in one pass.

---

## 3. Assembly Runtime Panic Guards

Compiled 64-bit NASM binaries include runtime safety check routines:
- `__corvus_panic_null`: Catches null pointer dereferences before OS segmentation fault.
- `__corvus_panic_bounds`: Catches array index out of bounds errors.
- `__corvus_panic_divzero`: Catches division by zero math errors.
