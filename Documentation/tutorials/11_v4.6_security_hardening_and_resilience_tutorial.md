# Corvus v4.6 Hands-On Tutorial: Enterprise Security Hardening & Robustness Engine

Welcome to **Corvus Version 4.6**!

Corvus v4.6 is a dedicated **Enterprise Security & Reliability Release**. It hardens the language runtime, standard libraries, bytecode deserializer, and compiler runners against vulnerabilities, malicious inputs, untrusted scripts, and denial-of-service vectors.

All improvements retain **100% backward compatibility** with previous Corvus versions, preserving the tri-engine architecture (AST Interpreter, Bytecode VM, and C99 Native Compiler).

---

## 🌟 What's New & Hardened in v4.6?

### 1. Zero Unsafe Subprocess Execution (`shell=False`)
* Unsafe `shell=True` subprocess calls have been removed across runtime process bridges and compiler drivers (`Compiler_Linux`, `Compiler_MacOS`, `std_process.py`, `evaluatorcorvus.py`).
* Safe tokenization using `shlex.split` prevents shell injection when running external tools or process tasks.
* Parameterized array execution: `process.run(["corvusc", "file.crv", "-o", "bin"])`.

### 2. SSRF & Denial-of-Service Defense (`std_net.py` & Builtin `http`)
* **Strict URL Scheme Whitelisting**: Only `http://` and `https://` schemes are permitted. Malicious schemas like `file://`, `gopher://`, or `ftp://` are immediately blocked with informative errors.
* **Payload Memory Bounds**: HTTP responses are capped at a strict 10 MB payload limit (`MAX_RESPONSE_BYTES`) to prevent memory exhaustion and DoS attacks.
* **TCP Port Bounds Checking**: Socket connections and listeners validate ports strictly in the `1 - 65535` range.

### 3. Path Traversal Protections (`file` & `http.download`)
* Path sanitization via `_validate_path` checks against directory traversal (`../`) and canonicalizes absolute targets before performing file writes or downloads.

### 4. Cryptographic Enhancements (`std_crypto.py`)
* **Key Validation**: Prevents division-by-zero or empty-key exceptions in XOR ciphers by requiring non-empty keys.
* **Cryptographically Secure Random Bytes**: New `crypto.random_bytes(length)` powered by system entropy (`secrets.token_hex`).
* **Modern Cryptographic Hashes**: Added `crypto.sha512(data)` and message authentication via `crypto.hmac_sha256(key, message)`.

### 5. Prepared SQLite Query Execution (`std_sqlite.py`)
* Enforces tuple/list parameter sequences when running parameterized SQL queries to prevent SQL injection vulnerabilities.

### 6. Bytecode Deserializer Bounds Checking (`bytecode.py`)
* Bytecode streams validate offset bounds (`_ensure_bytes`) on every unpack operation.
* Truncated, corrupted, or crafted malicious `.crvc` files throw clean, actionable `ValueError` exceptions rather than unhandled index crashes.
* Constant pool string lengths are bounded to prevent memory allocation bombs.

### 7. Virtual Machine Stack & Call Frame Guards (`vm.py`)
* Maximum operand stack depth (`MAX_STACK_SIZE = 100000`) and call frame recursion limits (`MAX_STACK_DEPTH = 10000`) prevent host interpreter stack overflows.
