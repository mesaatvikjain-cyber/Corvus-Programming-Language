# Corvus v4.1 Tutorial: Super High-Level Optimization Engine

**Version 4.1** introduced the **Super High-Level Optimization Engine** (`super_optimizer.py`), implementing 5 advanced compiler passes across Intermediate Representation (TAC IR) and Assembly Generation backends.

---

## 1. The 5 Optimization Passes

```text
[AST Source] ──> [TAC IR Generator] ──> [SuperOptimizer v4.1] ──> [Assembly Peephole Pass] ──> [Native Binary]
                                            │
                                            ├── 1. Constant Propagation Pass
                                            ├── 2. Algebraic Strength Reduction Pass
                                            ├── 3. Constant Branch Folding Pass
                                            ├── 4. CFG Jump Threading Pass
                                            └── 5. Standard Optimizer (CSE, DCE, Inlining)
```

---

## 2. Pass 1: Constant Propagation & Folding

Known constant variable declarations (`var a = 10; var b = 5`) are propagated across basic blocks before expression evaluation:
```corvus
var a = 10
var b = 5
var c = a * b + 2  # Propagated to: 10 * 5 + 2 -> Folded to: 52
```

---

## 3. Pass 2: Algebraic Strength Reduction & Bitwise Shifts

Expensive multiplication and division operations by powers of two ($2^k$) are converted into bitwise shift instructions:
- `x * 2` $\rightarrow$ `SHL x, 1`
- `x * 4` $\rightarrow$ `SHL x, 2`
- `x * 8` $\rightarrow$ `SHL x, 3`
- `x / 2` $\rightarrow$ `SHR x, 1`
- `x / 4` $\rightarrow$ `SHR x, 2`
- Algebraic Identies: `x * 0 -> 0`, `x + 0 -> x`, `x - 0 -> x`, `x * 1 -> x`, `x / 1 -> x`.

---

## 4. Pass 3 & 4: Constant Branch Folding & CFG Jump Threading

Constant conditions (`if (1)`) are evaluated at compile time, eliminating un-taken branch code paths, while chained jumps (`JMP L1` $\rightarrow$ `L1: JMP L2`) are collapsed into direct target jumps (`JMP L2`).

---

## 5. Pass 5: Assembly Peephole Optimization (`optimize_assembly`)

In the emitted NASM 64-bit assembly:
- Redundant store/load sequences (`mov qword [rel var_x], rax` followed by `mov rax, qword [rel var_x]`) are eliminated.
- Redundant self-register moves (`mov rax, rax`) are stripped.
